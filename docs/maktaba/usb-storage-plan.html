USB Storage Architecture

How to attach an external USB drive on the Proxmox host and share it safely across VMs — with unplug and power-loss resilience.

Core rule — non-negotiable

Only one system may mount the USB disk as a block device. Passing the same /dev/sdX to multiple VMs simultaneously will corrupt the filesystem. To share across guests, mount once on the Proxmox host and export via NFS/SMB (or bind-mount into LXCs).

2 Recommended architecture

Host mount + NFS export + bind mount into the Maktaba LXC for media only.

Why this pattern?

  • Single writer to the block device — no corruption risk
  • Other VMs mount proxmox-ip:/mnt/usb-data/shared over NFS
  • Maktaba uses a host bind mount (simpler permissions than NFS inside unprivileged LXC)
  • Elasticsearch, Redis, and configs stay on fast local CT disk

3 Folder layout on the host

/mnt/usb-data/ ├── maktaba/media/ ← TubeArchivist video files (~17 GB today, will grow) ├── shared/ ← other VMs / general LAN use └── backups/ ← optional: vzdump, backup.sh targets

Host fstab entry

# /etc/fstab on Proxmox host — use UUID, not /dev/sdX
UUID=<uuid>  /mnt/usb-data  ext4  defaults,noatime,nofail,x-systemd.device-timeout=10s  0  2

Bind mount into Maktaba LXC

# On Proxmox host
pct set <maktaba-ctid> -mp1 /mnt/usb-data/maktaba/media,mp=/srv/maktaba/data/media,backup=0

4 Filesystem choice

✓ ext4
Recommended
~ xfs
OK, no advantage
✗ ntfs/exfat
✗ ZFS on USB

ext4 — journaling, fast recovery after power loss, well understood on Linux. Use /dev/disk/by-id/usb-... for partitioning (not /dev/sdb, which can change after reboot).

sudo parted /dev/disk/by-id/usb-... mklabel gpt
sudo parted /dev/disk/by-id/usb-... mkpart primary ext4 0% 100%
sudo mkfs.ext4 -L usb-data /dev/disk/by-id/usb-...-part1

5 Unplug & power-loss resilience

USB will eventually disappear. Design for graceful degradation, not hot-swappable convenience.

stateDiagram-v2 direction LR [*] --> Attached: USB plugged in Attached --> Missing: Unplug / power loss Missing --> Attached: Reconnect + mount state Attached { [*] --> Serving Serving: NFS + bind mount active Serving: Downloads & playback OK } state Missing { [*] --> Degraded Degraded: nofail → host still boots Degraded: ES/Redis/config on local disk OK Degraded: Media I/O fails gracefully } note right of Missing Active writes may fail. Run umount before unplugging. end note

✓ Do

  • nofail in fstab — host boots without USB
  • umount before physical unplug
  • udev rules to stop/start containers on disconnect
  • SMART monitoring (smartctl)
  • Keep backups — USB ≠ backup

✗ Don't

  • Hot-unplug while writes are active
  • Put Elasticsearch on USB
  • Use soft NFS for media writes
  • Mount same block device in 2 VMs
  • Store VM disk images (qcow) on USB

Safe unplug procedure

sync
sudo umount /mnt/usb-data
sudo udisksctl power-off -b /dev/disk/by-id/usb-...

NFS mount for other VMs

# /etc/fstab on a VM — hard mount for data integrity
proxmox-ip:/mnt/usb-data/shared  /mnt/shared  nfs  vers=4.1,_netdev,hard,noatime,nofail,x-systemd.automount  0  0

7 Options compared

Host + NFS + bind
★★★★★ sharing · ★★★★ resilience · ★★★ complexity
  • Best for mixed VMs + LXCs
  • Low overhead
  • Maktaba bind mount is simple
OMV VM + passthrough
★★★★★ sharing · ★★★★★ USB handling · ★★★★ complexity
  • Best if USB unplugged often
  • Nice NAS UI for shares
  • Extra RAM/CPU for VM
USB passthrough to Maktaba only
★ sharing · ★★ resilience · ★ complexity
  • One consumer only
  • Fragile with disconnects
  • Other VMs can't share
Same USB → multiple VMs
⛔ Do not do this
  • Filesystem corruption
  • Proxmox GUI allows it — don't

8 Implementation phases

Phase 1 · Proxmox host

Prepare & mount USB

  1. Identify disk: lsblk -f and ls -l /dev/disk/by-id/usb-*
  2. Partition + format ext4
  3. Mount at /mnt/usb-data with fstab (nofail)
  4. Create maktaba/media, shared, backups
  5. Configure NFS export (or bind mount only if no other VMs yet)
Phase 2 · Maktaba migration

Move media off root disk

  1. Wire bind mount: pct set <ctid> -mp1 ...
  2. docker compose stop tubearchivist jellyfin
  3. rsync -aH data/media/ to new mount (if migrating in-place)
  4. Verify file count, restart stack
  5. Confirm df -h / drops to ~55%
Phase 3 · Harden

Disconnect handling & monitoring

  1. udev rule: stop containers on USB remove, restart on reconnect
  2. Extend healthcheck.sh — warn if mount missing
  3. Enable SMART monitoring
  4. Update documentation/handoff.md
